# Закрытый доступ к базе поставщиков (подписка)

Next.js + Supabase + CloudPayments. Платный доступ к контенту с лимитом устройств
и водяными знаками на контактах.

## Как работает защита

| Что | Как |
|-----|-----|
| Доступ только после оплаты | Флаг `paid` ставит **только** webhook CloudPayments (`/api/payment/webhook`) после проверки HMAC-подписи. Из браузера выдать доступ нельзя. |
| Подписка на срок | `access_until`. Истёк — контент закрывается. Оплата продлевает. |
| Не больше 2 устройств | Таблица `devices`, лимит `MAX_DEVICES`. Проверка в `checkAccess()` на сервере. |
| Защита контента | Контакты отдаются PNG-картинкой с диагональным водяным знаком (email покупателя). Прямого доступа к таблице `contacts` у клиента нет (нет RLS-политик select). |

> Полностью помешать перепечатать контакт вручную нельзя. Поэтому модель —
> подписка + регулярно обновляемая база, чтобы слитый список устаревал.

## Настройка

### 1. Supabase
1. Создайте проект на supabase.com.
2. В SQL Editor выполните `supabase/schema.sql`.
3. Authentication → Email: включите вход по магической ссылке (OTP).
4. Скопируйте URL, anon key и service_role key в `.env.local`.

### 2. CloudPayments
1. Подключите кассу, возьмите `Public ID` и `API Secret` (Пароль для API).
2. В настройках уведомлений укажите Pay-уведомление на
   `https://ВАШ-ДОМЕН/api/payment/webhook` (метод POST).
3. Внесите ключи в `.env.local`.

### 3. Запуск
```bash
cp .env.local.example .env.local   # заполнить значения
npm run dev
```

### 4. Добавить контакты
Вставляйте строки в таблицу `contacts` (Supabase Table Editor):
`title` — что видно в списке, `body` — сам контакт (рендерится в картинку).

## Важно
- Боевые ключи (`service_role`, `API Secret`) — только сервер, в браузер не отдаются.
- Webhook идемпотентен (уникальный `TransactionId`), повторы безопасны.
- Юридический риск: если оффер связан с чужой торговой маркой (бренды) —
  проверьте законность до запуска и не используйте чужие товарные знаки в названии/рекламе.
